## そのまま使える指示（コピペ用）

> **HTML / CSS / JavaScript だけで動く高校生向けの学習アプリ群を作ってください。** ビルド不要・フレームワークなし・外部 API なし（完全オフラインで動くこと）。
>
> 構成は次のとおり。
>
> ```
> 学習アプリ/
> ├── index.html        ← ポータル（教科を選ぶ。社会と理科が有効、数学・国語は「準備中」）
> ├── style.css  sw.js  manifest.webmanifest  icon-*.png
> ├── start.command  start.bat
> ├── 社会/
> │   ├── index.html    ← 分野を選ぶ（日本史・世界史・地理・政治・経済）
> │   └── <分野>/       ← 4つの学習アプリ
> └── 理科/
>     ├── index.html    ← 分野を選ぶ（物理・化学・生物・地学）
>     └── <分野>/       ← 4つの学習アプリ
> ```
>
> ### 共通エンジン
> 4分野の `app.js` は**同一**にし、分野ごとの違いは `data-units.js` 冒頭の `APP` オブジェクトに全部出す。
> ```js
> const APP = {
>   key, title, icon,
>   unitWord,          // 「時代」「分野」「単元」
>   listWord,          // 「年表」「統計」
>   leadUnits, searchPlaceholder,
>   cats,              // クイズの分野区分（4つ）
>   typeLabels,        // { sel, cmb, ord, src } の表示名
>   typeNotes,         // 出題形式の説明文（配列）
>   wordsHeads,        // 用語タブの2つの見出し（例: ['重要用語','まちがえやすい区別']）
>   kinds,             // 検索結果の種別ラベル { word, person, event }
> };
> ```
> `apps.json` 側では `listIcon`（一覧タブの絵文字）と `themeWord`（テーマタブの呼び名）も指定する。
> `app.js` の `applyBranding()` が起動時に画面へ反映する。**分野を増やすときに `app.js` を触らないこと**が設計の目標。
>
> ### データ構造
> - `UNITS`: `{ id, name, yomi, span, n0, n1, icon, color, catch, summary[], sections[{t,items[{h,b}]}], keywords[{w,y,d}], people[{n,y,d}], events[{n,y,t,d}], topics[{t,lead,body[]}] }`
> - `QUIZ`: `{ id, era, type, cat, lv, q, src?, choices[], a, exp }`
> - `THEMES`: `{ id, icon, title, color, lead, steps[{era,t,b}] }`
> - 各ファイル末尾に `if (typeof module !== 'undefined') { module.exports = {...}; }` を置き、Node から検証できるようにする。
>
> ### 各アプリの中身（1分野あたり）
> - **単元15個**。それぞれ 概要3段落／詳細3〜5見出し×3〜5項目（合計160以上）／重要用語8〜14／人物・事例4〜13／年表または統計6〜16／トピック1〜2本（「なぜそうなったのか」を掘り下げた読み物、本文4〜6段落）。
> - **テーマ史5〜6本**。単元をまたぐ流れを7〜9ステップで整理。
> - **クイズ180問以上**（1単元12問以上）。大学入学共通テストの出題形式に合わせる。
>   - `sel`「〜について述べた文として正しいもの（誤っているもの）を、次の①〜④のうちから一つ選べ」
>   - `cmb`「次の文a〜dについて、正しいものの組合せを、下の①〜④のうちから一つ選べ」。選択肢は `a・c` `a・d` `b・c` `b・d` で固定
>   - `ord`「次の文Ⅰ〜Ⅲについて、古いものから年代順に（数値の大きい順に）正しく配列したものを、下の①〜⑥のうちから一つ選べ」。選択肢は `Ⅰ−Ⅱ−Ⅲ` 〜 `Ⅲ−Ⅱ−Ⅰ` の6通りを固定の順で
>   - `src` 史料・条文・統計表を読ませる問題
>   - `exp`（解説）は**なぜ他の選択肢が誤りなのか**まで書く。ここが学習の本体。
>   - 誤答選択肢は「別の時代・別の人物・別の制度を混ぜた、ありそうな間違い」にする。

> ### 実装上の必須事項
> - **`ord` と `cmb` の選択肢はシャッフルしない。** 並び自体が設問の一部。シャッフルは `sel` と `src` のみ。
> - 保存は localStorage の1キー（`APP.key`）。`load()` で既定値とマージし、読み書きは try/catch。
> - 色はすべて CSS 変数。ダークは `@media (prefers-color-scheme: dark)` と `:root[data-theme="dark"]` の**両方**に定義。ダークでは `--primary-text` を暗い色にし、ヘッダーは別変数で濃い色＋白に固定。
> - `color-mix()` を使う直前にフォールバックの `background` を書く。
> - 480px 以下ではタブをアイコンのみ（選択中だけラベル）にし、カードを1列にする。
> - PWA 一式（manifest / sw.js / アイコン4種）。ポータルと各アプリがそれぞれ Service Worker をもつ。`index.html` から CSS/JS を `?v=N` 付きで読み、更新のたびに `sw.js` の `CACHE` と同じ番号で上げる。
> - 起動スクリプト（`start.command` / `start.bat`）。ポータルは8771、各アプリは8766〜8769。**使用前に `lsof` で空きを確認すること。**

## 作成順（段階的に作る場合）

1. **1分野を単独で完成させる**（日本史がおすすめ）。データ構造・画面・クイズ形式をここで固める。
2. **雛形化する。** 完成した `index.html` / `style.css` / `app.js` から、分野ごとに変わる部分を `APP` へ追い出し、フォルダへ生成するスクリプトをつくる。以後は**雛形を直して再生成**する。
3. **検証スクリプトを先につくる。** 件数・単元別内訳・id重複・正解インデックスの範囲・選択肢数・形式別件数・言語チェックを1コマンドで確認できるようにする。
4. **2分野目以降のデータを書く。** 3〜4単元ずつ追記しては検証、をくりかえす。1回の生成で全部書こうとしない。
5. **クイズを書く。** こちらも3〜4単元ずつ。単元×形式のクロス集計で偏りを確認する。
6. **ポータルをつくる。** 教科選択 → 分野選択 → 各アプリ。各アプリに戻るリンクを足して再生成。
7. **ブラウザで全件確認。** 「全単元×全サブタブを開く」「全問を表示して採点する」をコンソールから一括実行する。
8. **ドキュメント**（`README.md` / `設計書.md` / `知見.md` / `再現プロンプト.md`）。

## 作るときに必ず守ること（実際にやらかした点）

- 画面に出る日本語を `app.js` に直書きしない。分野によって変わる語（時代／分野／単元、年表／統計、史料／資料）は必ず `APP` へ。**とくにクイズの分野区分（`cats`）を直書きすると、別分野で出題が無言で0件になる。**
- `ord` と `cmb` の選択肢はシャッフルしない。
- クイズの `id` は学習記録の主キー。あとから変えない。参照側は `.filter(Boolean)` する。
- 長い日本語データは、構文チェックだけでなく**中身の言語**も機械的に確認する。ただしファイル全体を grep せず、Node で本文フィールドだけを調べる。
- ダークモードでは「ブランド色の上の文字色」も反転させる。背景用と文字用で CSS 変数を分ける。
- ファイルを変えたら `?v=` と `CACHE` を必ず上げる。ローカル確認のときも。
- ポートは使用前に空きを確認する。「200が返る」はサーバーが正しいことを意味しない。**返ってきた中身**を見る。
- 画面に出るのは `APP` の値だけでなく、**雛形HTMLに直書きした絵文字やタブ名**もある。理科では「🗓️年表」「テーマ史」が社会の語のまま残った。`index.base.html` の固定文字列も `apps.json` から差し替えられるようにしておく。
- 言語チェックは教科で基準が変わる。社会は2文字以上のラテン文字をすべて疑えばよいが、理科では `mg` `kx` `ZnSO` `IBLsinθ` のような数式・化学式が大量に出る。**4文字以上で、かつ「全部小文字」か「先頭だけ大文字」の語**（＝ふつうの英単語の形）だけを検出する、と切り替える。
- `ord`（大小配列）では、**3つの値が同じにならないように**作る。同点があると正解が一意に決まらない。作問後に値を並べて確認する。
- 公開する前に、HTMLの `src` と `href` に**絶対パス（`/` で始まるもの）が1つもない**ことを確かめる。サブディレクトリ公開（`example.com/gakushu/`）で動かなくなる。
