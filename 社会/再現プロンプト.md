## そのまま使える指示（コピペ用）

> **HTML / CSS / JavaScript だけで動く高校生向けの学習アプリ群を作ってください。** ビルド不要・フレームワークなし・外部 API なし（完全オフラインで動くこと）。
>
> 構成は次のとおり。
>
> ```
> 学習アプリ/
> ├── index.html        ← ポータル（教科を選ぶ。社会・理科・数学・国語・英語）
> ├── style.css  sw.js  manifest.webmanifest  icon-*.png  .nojekyll
> ├── search.js  search-index.js   ← ポータル・教科ページの検索
> ├── start.command  start.bat
> ├── tools/tpl/        ← 雛形と生成・検証スクリプト（後述）
> ├── 社会/
> │   ├── index.html    ← 分野を選ぶ（日本史・世界史・地理・政治・経済・倫理）
> │   ├── 設計書.md  知見.md  再現プロンプト.md
> │   └── <分野>/       ← 5つの学習アプリ
> ├── 理科/
> │   ├── index.html    ← 分野を選ぶ（物理・化学・生物・地学）

> ├── 数学/
> │   ├── index.html    ← 分野を選ぶ（数学Ⅰ・A／Ⅱ・B／Ⅲ・C）

> ├── 国語/

> ### 共通エンジン
> 全分野の `app.js` は**同一**にし、分野ごとの違いは `data-units.js` 冒頭の `APP` オブジェクトに全部出す。
> ```js
> const APP = {
>   key, title, icon,
>   unitWord,          // 「時代」「分野」「単元」
>   listWord,          // 「年表」「統計」「公式」「データ」「文法」「句法」「重要表現」
>   leadUnits, searchPlaceholder,
>   cats,              // クイズの分野区分（4つ）
>   typeLabels,        // { sel, cmb, ord, src } の表示名
>   typeNotes,         // 出題形式の説明文（配列）
>   wordsHeads,        // 用語タブの2つの見出し（例: ['重要用語','まちがえやすい区別']）
>   kinds,             // 検索結果の種別ラベル { word, person, event }
> };
> ```
> `apps.json` 側では `listIcon`（一覧タブの絵文字）と `themeWord`（テーマタブの呼び名）、`wordsTab`（用語タブ名）も指定する。
> `app.js` の `applyBranding()` が起動時に画面へ反映する。**分野を増やすときに `app.js` を触らないこと**が設計の目標。
>
> ### データ構造
> - `UNITS`: `{ id, name, yomi, span, n0, n1, icon, color, catch, summary[], sections[{t,items[{h,b}]}], keywords[{w,y,d}], people[{n,y,d}], events[{n,y,t,d}], topics[{t,lead,body[]}] }`
> - `QUIZ`: `{ id, era, type, cat, lv, q, src?, choices[], a, exp }`
> - `THEMES`: `{ id, icon, title, color, lead, steps[{era,t,b}] }`
> - 各ファイル末尾に `if (typeof module !== 'undefined') { module.exports = {...}; }` を置き、Node から検証できるようにする。
>
> ### 説明にそえる図・表・地図・写真
> 文字だけの説明は読み通せない。単元の説明には必ず図版をそえる。**`UNITS` には書かず、分野ごとの `data-figs.js` に外付けする**（`UNITS` は数千行あり、図版を足すために触ると壊しやすいため）。
> ```js
> const FIGS = {
>   <単元id>: [
>     { at: 'ov',   k: 'table', t: '見出し', cap: '説明', head: ['列1','列2'], rows: [['…','…']] },
>     { at: 'sec1', k: 'svg',   t: '見出し', cap: '説明', svg: '<svg viewBox="…" role="img">…</svg>' },
>     { at: 'sec2', k: 'map',   t: '見出し', cap: '説明', svg: '<svg …>…</svg>' },
>     { at: 'ov',   k: 'photo', t: '見出し', cap: '説明', src: 'img/xxx.jpg',
>       credit: 'ウィキメディア・コモンズ「…」（Public domain）' },
>   ],
> };
> ```
> - `at` は出す場所。`'ov'` は概要の要約の下、`'secN'` は詳細の第N節の下（0から数える）。
> - **全単元に1点以上**入れる。「効きそうな単元だけ」にすると見た目が不ぞろいになり、かえって読みにくい。目安は1分野20〜60点。
> - 題材で種類を選ぶ。表は活用表・句法・年表・分類、図は手順・対比・時間の流れ、地図は歴史と地理、写真は遺跡・生物・地形・人物。
> - **SVG に色を直書きしない。** `var(--primary)` `var(--text)` `var(--muted)` `var(--surface)` `var(--surface2)` `var(--border)` などの CSS 変数だけで塗る。そうしないと暗い画面やセピアで読めなくなる。`viewBox` と `role="img"` は必須。
> - 写真は **Public domain・CC0・No restrictions のものだけ**。ウィキメディア・コモンズの API で `extmetadata.LicenseShortName` を機械的に確かめてから落とす。目で見て選ぶと必ず取り違える。1枚130KB以下に縮め、`credit` に出どころを書く。
> - 検証は `node tools/check/figs.js`。単元IDと出す場所が実在するか、表の列数がそろっているか、SVGが閉じているか・色を直書きしていないか、写真の権利と大きさ、**図の中も含めて**日本語以外の文字がまぎれていないかを見る。
>
> ### 各アプリの中身（1分野あたり）
> - **単元15個**。それぞれ 概要3段落／詳細3〜5見出し×3〜5項目（合計160以上）／重要用語8〜14／人物・区別4〜13／年表または統計6〜16／トピック1〜2本（「なぜそうなったのか」を掘り下げた読み物、本文4〜6段落）。
> - **テーマ史5〜6本**。単元をまたぐ流れを7〜9ステップで整理。
> - **クイズ180問以上**（1単元12問以上）。大学入学共通テストの出題形式に合わせる。
>   - `sel`「〜について述べた文として正しいもの（誤っているもの）を、次の①〜④のうちから一つ選べ」
>   - `cmb`「次の文a〜dについて、正しいものの組合せを、下の①〜④のうちから一つ選べ」。選択肢は `a・c` `a・d` `b・c` `b・d` で固定
>   - `ord`「次の文Ⅰ〜Ⅲについて、古いものから年代順に（数値の大きい順に）正しく配列したものを、下の①〜⑥のうちから一つ選べ」。選択肢は `Ⅰ−Ⅱ−Ⅲ` 〜 `Ⅲ−Ⅱ−Ⅰ` の6通りを固定の順で
>   - `src` 史料・条文・統計表・本文資料を読ませる問題
>   - `exp`（解説）は**なぜ他の選択肢が誤りなのか**まで書く。ここが学習の本体。
>   - 誤答選択肢は「別の時代・別の人物・別の制度を混ぜた、ありそうな間違い」にする。
> - 形式の比率は `sel` 半分、`cmb` `ord` `src` 各6分の1が目安（例: 180問なら 90 / 30 / 30 / 30）。

> - **配当漢字は推測で書かない。** 漢検協会の「級別漢字表」（2020年2月発表）から機械的に取り出し、185字ちょうどであること・重複がないことを検証する。音訓・部首・画数は「常用漢字表」（2010年内閣告示）による。
> - `events` を**漢字一覧**として使う。1字につき `y` に「部首・画数」、`t` に漢字、`d` に「音読み／訓読み・熟語・例文」を入れる。これで一覧タブがそのまま漢字辞典になり、漢字・読み・熟語のどれでも絞り込める。
> - `ord` は年代や大小ではなく**総画数の多い順**の配列にする。画数は数え間違えやすいので、公式の画数データから問題を生成する。
> - `src` は資料ではなく**短文**。短い文の傍線部について、漢字に直す問題と読みを答える問題を出す。
> - 許容字体のある字（𠮟・塡・頰・剝）は、表示の確実な許容字体（叱・填・頬・剥）を見出しに使い、本則の字体を注記する。
> - 例文はすべて書き下ろしとし、実在の作品は引用しない。
>
> ### 英語3分野の内容

> - **英文読解**（単元／読解の技法／英文資料）: 文の骨格をつかむ・修飾の範囲・指示語・つなぎ語・段落の構成・要旨のとらえ方・推論・筆者の意図と表現・図表の読み取り・複数資料の照合・実用文・物語文・語彙の推測・設問の型・総合演習。分野区分は 文の構造／論理の展開／設問の型／資料と実用文。基調色は煉瓦色、ゴシック体。
> - **語彙と表現**（単元／重要表現／英文資料）: 基本動詞・句動詞・多義語・接辞と語源・類義語の使い分け・前置詞の語感・コロケーション・名詞の語彙・場面別の表現・文化と背景・反意語・数量表現・省略と指示・語彙学習の方法・総合演習。分野区分は 基本動詞と句動詞／語の成り立ち／意味のつながり／場面と表現。基調色は苔緑、ゴシック体。
>
> 英語では `events` を**重要表現・文法事項**、`people` を**まちがえやすい区別**として使う。
> `ord` は**順序配列**（読み取る手順の順、文中に現れる順など）。`src` は**英文資料**。
> **解説はすべて日本語で書き、英語は例として示す。** 英文には必ず訳と考え方を添える。
> 英文資料もすべて書き下ろしとし、実在の文章は引用しない。

> ### 英検2級（検定対策の分野）
> - **英検2級**（単元／単語／短文）: 英検2級に必要な単語・熟語1500語を、場面と品詞で15単元に分ける。
>   暮らしと家族・学校と学び・仕事と職場・買い物とお金・食事と健康・旅行と交通・自然と環境・社会と制度・
>   科学と技術・文化とスポーツ・心と感情・考えと意見・性質と程度・動作と変化・熟語と句動詞。
>   分野区分は 名詞／動詞／形容詞・副詞／熟語・句動詞。基調色は琥珀、ゴシック体。
> - **1語1項目を守る。** 1500語が本当に1500の別々の語になっているか、機械で確かめる。
>   同じ語を二つの単元に入れると、単語帳としての数が合わなくなる。
> - `events` を**単語帳**として使う。1語につき `y` に品詞、`t` に語、`d` に「意味。例文（訳）」を入れる。
> - `ord` は年代でも大小でもなく**程度配列**にする。annoyed → angry → furious のように、
>   弱い順や順序に意味のある三つ組を単元ごとに二つ用意する。`src` は**短文**（空所補充）。
> - 例文はすべて書き下ろし。実在の文章は引用しない。
>
> ### 発音記号と読み上げ
> - 語を覚える分野では、語の横に**発音記号**を出し、🔊 で端末の音声に読ませる。
>   `APP.speak` に言語を入れた分野にだけボタンを作る。立てていない分野は何も変わらない。
> - 音声は端末のものを使う。**ネットにはつながらない**ので、オフラインでもそのまま鳴る。
>   その言語の声が無い端末では、そう書いて知らせる。
> - 読み物（文学書）でも章の本文を読み上げる。長い段落は文ごとに切って渡すこと。
>   一度に長い文を渡すと途中で切れる端末がある。ルビの読みは二重に読まれるのでたどらない。
>
> ### 対照表示
> 原文と訳を一段ずつ並べる。**訳を原文と1段落ずつ対応させて作った章だけ** `aligned` を立てる。
> 数が合わないまま立てると、訳がずれて並ぶ。
>
> ### 単語帳（意味をかくす）
> 語を覚える分野では、一覧タブを単語帳として使えるようにする。
> `APP.cardMode` を立てた分野にだけ「意味をかくす」ボタンを出し、押すと説明が帯で隠れる。
> その行をおすと一つずつ出る（赤シートと同じ使い方）。
> **立てていない分野ではボタンを作らない**ので、ほかの分野は何も変わらない。
> 状態は分野ごとの localStorage に残す。
>
> ### 読み物アプリ（クイズのない3分野）
> 国語に2つ、英語に1つ、クイズのない読み物を置く。`app.js` は3分野で**同一**にし、違いは `data-works.js` 冒頭の `APP` と作品ごとの指定だけに出す。
> - **古典文学**: 竹取物語（全9段）・源氏物語（全54帖）・枕草子・土佐日記・平家物語。原文と現代語訳を切り替えて読め、短い作品は一段ずつ並べた「対照」でも読める。
> - **近現代文学**: 青空文庫から、必須の文学書20冊と分野別の代表作10冊。あわせて、書いた文豪26人の紹介（顔写真・生没年・出身・略歴・人物像・作風と主張・ほかの代表作）を置く。
> - **英米文学**: 英米の名作を英語の原文で読む。原文はプロジェクト・グーテンベルク、日本語訳は青空文庫の保護期間満了のものだけ。章ごとに**語注**（英検2級の語彙をこえる語）を付け、書いた作家の紹介も置く。
> - データは `WORKS`（作品と巻の見出し・要約）・`AUTHORS`（文豪）・`NOTES`（語注。キーは「作品id/章番号」）。本文は `text/<作品id>/NN.js` に分け、**開いた巻だけ**を `<script>` の差しこみで読む。一度に読むと重すぎる。
> - `AUTHORS` も `NOTES` も、置いた分野にだけ出す。`app.js` は「要素とデータの両方があるときだけ描く」という一行の分岐で済ませ、分野ごとにファイルを分けない。
> - **作品を持たず人物だけを並べる分野**も同じエンジンで作れる（理科の「日本人のノーベル賞」）。`WORKS` を空にすると人物一覧が入口になる。人物ページの見出しは `APP.authorSections` で差し替える。
> - 段落は文字列の**先頭1文字で種類を表す**（`p` 地の文 / `v` 韻文 / `c` 右寄せ / `h` 小見出し / `w` 和歌）。大文字にすると前に1行ぶんの空きが入る。空行を別の要素にしないための約束。
> - ふりがなは青空文庫の記法 `｜漢字《よみ》` をデータにそのまま残し、表示するときに `<ruby>` へ組み立てる。外字は取りこみの時点で実際の文字に直す。
> - `sw.js` のキャッシュを**2つに分ける**。骨組みは版つき（`kotenbungaku-v8`）、本文は版なし（`kotenbungaku-text`）。こうすると更新しても、まとめて保存した本文が消えない。
> - 巻ごとの要約・作品解説・文豪の紹介文・語注はすべて書き下ろし。本文は保護期間が満了したものか CC0 のものだけ。
> - **語注の見出しは、その章の原文に実在する語だけにする。** 記憶で書くと必ず入っていない語がまぎれるので、検証で原文と突き合わせる。
> - 日本語訳の採否は、青空文庫の目録の**著作権フラグ**と**文字遣い種別**の両方で決める。旧字旧仮名の訳は学習の助けにならないので、何であるかを明示して併載するにとどめる。
>
> ### 画面（19分野共通）
> 7タブ: 単元 / 年表・統計 / テーマ史 / トピック / クイズ / 記録 / 保存。右上に 🔍全文検索 と ⚙設定。ヘッダー左に `◀`（分野一覧へもどる）。
> - **単元**: カード一覧（単元色の左線・絵文字・サブタイトル・キャッチ、既読なら「読了」バッジ）→ 詳細。詳細はヒーロー＋6サブタブ（概要／詳細／用語・人物／年表・統計／トピック／クイズ）。概要では要約の直後、詳細では節ごとの末尾に図版が入る。`◀ ▶` で前後の単元へ（サブタブは維持）。開いた時点で既読にする。
> - **年表・統計**: 全単元を通しで一覧。単元チップで絞り込み、テキスト検索で該当語を `<mark>` でハイライト。単元バッジのタップで詳細へ。
> - **トピック**: 最初は折りたたみ、「続きを読む ▼」で展開。
> - **クイズ**: 単元・分野・形式をチップで複数選択（空になったら自動で全選択に戻す）、問題数（5/10/20/すべて）、「苦手な問題を優先」。出題対象数を常時表示。回答で正解を緑・誤答を赤に着色し解説を表示。最後に得点・正答率・講評・まちがえた問題の解説一覧。
> - **記録**: 解いた問題数／通算正答率／読んだ単元／学習した日数のタイル、単元別・分野別の正答率バー、読了状況、まちがえた問題トップ10。
> - **保存**: ☆した用語と、保存した問題（解答と解説つき）。
> - **設定**: よみがな表示 / 選択肢シャッフル / 文字サイズ4段階 / 配色（端末に合わせる・ライト・ダーク）。
>
> ### 検索（3階層）
> 全体・教科・科目のそれぞれに検索を置く。
> - **各アプリ**: 年表・統計・用語の一覧をキーワードで絞り込み、該当語を `<mark>` でハイライト。
> - **ポータルと教科ページ**: 共通の `search.js` と、生成した `search-index.js`（`SEARCH_FIELDS` と `SEARCH_UNITS`）を読む。索引には単元の見出しと用語・人物の**名前だけ**を入れ、説明文は入れない（容量が跳ね上がるため。19分野285単元と読み物を合わせて610項目・用語4729件で約260KB）。
> - 絞り込みは `document.body.dataset.subject`（教科ページでは教科名、ポータルでは空）で行い、リンクの相対パスは `document.body.dataset.base` で切り替える。1つの `search.js` を両方で使う。
> - 検索結果から単元を開けるよう、各アプリの `app.js` に `#u=<単元ID>`（任意で `&s=<サブタブ>`）を読むハンドラを置き、`hashchange` と初回読み込みの両方で動かす。
> - 索引は全分野の `data-units.js` を走査して作り直す（`tools/tpl/mkindex.js`）。**分野を足したら必ず作り直し、ポータルと全教科ページの `?v=` を同じ番号に揃える。**
>
> ### 生成と検証のしくみ（`tools/tpl/`）
> 19分野を手で並べると破綻するので、UI は雛形から生成する。
>
> | ファイル | 役割 |
> |---|---|
> | `app.base.js` | エンジンの原本（日本史アプリの `app.js`）。生成時に `ERAS`→`UNITS` などを置換して各分野へ配る |
> | `index.base.html` | 画面の骨組みの原本。タブ名・絵文字・プレースホルダーも `apps.json` から差し替える |
> | `style.base.css` | 配色とフォントを差しこむ原本 |
> | `apps.json` | 分野ごとの設定（`dir` `subject` `slug` `port` `title` `icon` 配色20色 `unit` `list` `wordsTab` `listIcon` `themeWord` `kinds` …） |
> | `gen.py` | `apps.json` の各分野へ `index.html` / `style.css` / `app.js` / `sw.js` / `manifest` / 起動スクリプトを生成。出力先は**スクリプトの位置から求める**（`GEN_BASE` で上書き可） |
> | `mkindex.js` | 全分野の単元データから `search-index.js` を生成 |
> | `check.sh` | 1分野分のデータ検証（件数・単元別内訳・ID重複・正解インデックス・選択肢数・形式別件数・言語チェック） |
>
> データを書いたら必ず `check.sh <教科>/<分野>` を通す。確かめるのは次の7点。
> 1. 総数と単元別の内訳（各単元12問以上） 2. `id` の重複なし 3. `0 <= a < choices.length`
> 4. `ord` は6択・それ以外は4択 5. `type:'src'` に `src` 本文がある 6. `era` が `UNITS` に実在する
> 7. 本文（`q` / `src` / `exp` / `choices`）に日本語以外の語が混入していない
>
> **7の基準は教科によって変える。** 同じ規則では使えない。
>
> | 教科 | 基準 | 理由 |
> |---|---|---|
> | 社会・国語 | 2文字以上のラテン文字をすべて疑う（`GDP` `SNS` などは許可リスト） | `village` `market` のような混入を拾いたい |
> | 理科・数学 | **4文字以上で、かつ「全部小文字」か「先頭だけ大文字」の語**だけ | `mg` `ZnSO` `IBLsinθ` のような化学式・数式を除くため |
> | 英語 | ラテン文字は検出しない。**キリル文字・ハングル・アラビア文字だけ**を検出 | 例文が英語なので、ラテン文字を疑うと全部ひっかかる |
>
> ### 実装上の必須事項
> - **`ord` と `cmb` の選択肢はシャッフルしない。** 並び自体が設問の一部。シャッフルは `sel` と `src` のみ。
> - 保存は localStorage の1キー（`APP.key`。`nihonshi.v1` `rinri.v1` `suugaku1a.v1` のように分野ごと）。`load()` で既定値とマージし、読み書きは try/catch。
> - 色はすべて CSS 変数。ダークは `@media (prefers-color-scheme: dark)` と `:root[data-theme="dark"]` の**両方**に定義。ダークでは `--primary-text` を暗い色にし、ヘッダーは別変数で濃い色＋白に固定。
> - `color-mix()` を使う直前にフォールバックの `background` を書く。
> - 480px 以下ではタブをアイコンのみ（選択中だけラベル）にし、カードを1列にする。
> - PWA 一式（manifest / sw.js / アイコン4種）。ポータルと各アプリがそれぞれ Service Worker をもつ。`index.html` から CSS/JS を `?v=N` 付きで読み、更新のたびに `sw.js` の `CACHE` と同じ番号で上げる。
> - 起動スクリプト（`start.command` / `start.bat`）。ポータルは8771、各アプリは8766〜8785を1つずつ割り当てる（日本史8766／世界史8767／地理8768／政治・経済8769／倫理8776／物理8772／化学8773／生物8774／地学8775／数学Ⅰ・A 8777／Ⅱ・B 8778／Ⅲ・C 8779／現代文8780／古文8781／漢文8782／英文法8783／英文読解8784／語彙と表現8785／漢検2級8786／古典文学8787／近現代文学8788／英米文学8789／日本人のノーベル賞8790／英検2級8791）。**使用前に空きを確認すること。**
> - HTML の `src` / `href` に**絶対パス（`/` で始まるもの）を書かない**。サブディレクトリ公開（`example.com/gakushu/`）で動かなくなる。

## 作成順（段階的に作る場合）

1. **1分野を単独で完成させる**（日本史がおすすめ）。データ構造・画面・クイズ形式をここで固める。
2. **雛形化する。** 完成した `index.html` / `style.css` / `app.js` を `tools/tpl/*.base.*` に移し、分野ごとに変わる部分を `APP` と `apps.json` へ追い出して、各フォルダへ生成するスクリプト（`gen.py`）をつくる。以後は**雛形を直して再生成**する。
3. **検証スクリプトを先につくる**（`check.sh`）。件数・単元別内訳・id重複・正解インデックスの範囲・選択肢数・形式別件数・言語チェックを1コマンドで確認できるようにする。
   このリポジトリの完成形は [tools/check/](../tools/check/) にある（`node tools/check/all.js` で全19分野。使い方・教科ごとの言語チェック基準・組合せの選択肢2種類は [tools/check/README.md](../tools/check/README.md)）。偏りを直す側は [tools/fix/](../tools/fix/)。
4. **2分野目以降のデータを書く。** 3〜4単元ずつ追記しては検証、をくりかえす。1回の生成で全部書こうとしない。
5. **クイズを書く。** こちらも3〜4単元ずつ。単元×形式のクロス集計で偏りを確認する。
6. **教科を足す。** 教科フォルダ（`理科/` など）と教科ページ（分野選択）をつくり、`apps.json` に `subject` を足して生成する。各アプリに戻るリンクを足して再生成。
7. **ポータルと3階層の検索をつくる。** 教科選択 → 分野選択 → 各アプリ。`mkindex.js` で索引を作り、ポータル・全教科ページの `?v=` を揃える。
8. **説明に図・表・地図・写真を入れる。** 分野ごとに `data-figs.js` を書き、全単元に1点以上そえる。写真を使う分野は、先に権利を機械で確かめる取りこみ口を作ってから集める。
9. **読み物を足す。**（必要なら）作品の選定 → 本文の取りこみと外字の解決 → 巻ごとの要約 → 著者紹介。本文はあとから足せるよう、キャッシュを骨組みと分けておく。
10. **ブラウザで全件確認。** 「全単元×全サブタブを開く」「全問を表示して採点する」をコンソールから一括実行する。
11. **ドキュメント**（`README.md` / `設計書.md` / `知見.md` / `再現プロンプト.md` / `公開手順.md`）。分野や機能を足したら、**そのたびに**直す。あとでまとめて直そうとすると、古い数字が何十か所にも散らばる。

実際にこの順で、日本史1本 → 社会5分野 → 理科4分野 → 数学3分野 → 国語4分野 → 英語3分野（計19分野・3455問）まで広げ、そのあと読み物2分野と、全19分野の図版625点を足した。
1教科ぶん（3〜5分野）を足すサイクルは「雛形に教科の設定を足す → 分野ごとに単元データ → クイズ → 検証 → 索引再生成 → ポータルに追加」で固定されている。

## 作るときに必ず守ること（実際にやらかした点）

- 画面に出る日本語を `app.js` に直書きしない。分野によって変わる語（時代／分野／単元、年表／統計、史料／資料）は必ず `APP` へ。**とくにクイズの分野区分（`cats`）を直書きすると、別分野で出題が無言で0件になる。**
- 画面に出るのは `APP` の値だけでなく、**雛形HTMLに直書きした絵文字やタブ名**もある。理科では「🗓️年表」「テーマ史」が社会の語のまま残った。`index.base.html` の固定文字列も `apps.json` から差し替えられるようにしておく。
- `ord` と `cmb` の選択肢はシャッフルしない。
- クイズの `id` は学習記録の主キー。あとから変えない。参照側は `.filter(Boolean)` する。
- 長い日本語データは、構文チェックだけでなく**中身の言語**も機械的に確認する。ただしファイル全体を grep せず、Node で本文フィールドだけを調べる。教科ごとの基準は上の表のとおり。
- ダークモードでは「ブランド色の上の文字色」も反転させる。背景用と文字用で CSS 変数を分ける。
- ファイルを変えたら `?v=` と `CACHE` を必ず上げる。ローカル確認のときも。
- 分野を足したら `mkindex.js` で索引を作り直し、**ポータルと全教科ページ（5枚）の `?v=` を同じ番号に揃える。** 1枚でも忘れると、そのページだけ古い索引を読み続ける。
- ポートは使用前に空きを確認する。「200が返る」はサーバーが正しいことを意味しない。**返ってきた中身**を見る。
- `ord`（大小配列）では、**3つの値が同じにならないように**作る。同点があると正解が一意に決まらない。作問後に値を並べて確認する。
- **`cmb`（組合せ）は、選択肢が `['a・c','a・d','b・c','b・d']` に固定されている。** したがって正しい文は **{a,b} からちょうど1つ、{c,d} からちょうど1つ**でなければならない。a と b の両方を正しくすると、どの選択肢にも当てはまらない問題ができてしまう（実際に8問作ってしまった）。検証スクリプトで `/^[ab]・[cd]$/` を機械的に確認する。
- **解説に書いた番号と `a` が食い違う**事故が起きる。解説の「正解は①」を正規表現で抜き出し、`a` と突き合わせる検査を入れる。
- `cmb` と `ord` はシャッフルされないので、**正解位置の偏りがそのまま出る**。形式ごとに正解インデックスを集計し、`cmb` は35%、`ord` は30%を超えないようにする。偏ったときは文の中身を入れ替えて正解位置をずらす（解説の番号と記号の言及も合わせて入れ替える）。
- **偏りは分野を足すたびに測り直す。** 1分野だけ見てもわからない。実際、途中で気づいて以降の9分野は直したのに、先に作った社会・理科の8分野は `cmb` の正解が全問①のまま残っていた（221問）。あとから一括で直した。
- 一括で直すときは、**分野ごとの書き方の揺れ**に注意する。組合せの選択肢が2通りある、記号のあとの区切りが半角と全角の両方ある、解説の書き出しが「正解は①a・c。」と「a・bが正しい。」の2通りある、など。区切りは決め打ちせずデータから読む。
- 記号の置換は単語の一部を巻き込むので（`independently` の `d` など）、前後が英数字でないものだけを対象にする。直したあとは、解説が「正しい」「誤り」と呼ぶ記号と `a` の指す選択肢を機械的に突き合わせる。ブラウザの全問採点では解説の矛盾は見つからない。
- その入れ替えを機械的にやるときは、**置換範囲を `exp:` 以降に限定する**。`ord` で Ⅰ Ⅱ Ⅲ のラベルを問題ブロック全体に置換したら、設問文と `choices` まで書き換わって正解が合わなくなった。
- 数学では**数式を記号で書かず、日本語の言葉で書く**（「2乗」「平方根」「導関数」）。記号を使うと言語チェックに引っかかるうえ、端末によって表示が崩れる。
- 書き下ろしか引用かの方針は、**教科を足す最初の時点で決めて README に書く**。現代文・英語の本文資料は書き下ろし、古文・漢文は保護期間を過ぎた古典のみ。
- 公開する前に、HTMLの `src` と `href` に**絶対パス（`/` で始まるもの）が1つもない**ことを確かめる。
- パスを持つスクリプト（生成・検証）は、**フォルダを動かした時点で壊れていると考える。** 絶対パスを書かず、スクリプトの位置から求める。
- 図の SVG に色を直書きしない。暗い画面で読めなくなる。検証で `#rrggbb` を弾く。
- 写真の権利は、目で見て選ばず**機械で確かめる**。落とす前にライセンス表示を見て、Public domain・CC0・No restrictions でなければ落とさない。
- **言語チェックは、人が文字を書ける場所すべてに掛ける。** 表のセルだけを見ていて、図（SVG）の中に書いたロシア語を取りこぼした。長い日本語を大量に書くほど、外国語の混入は確実に起きる。
- 大きなデータファイル（`UNITS` など）に後から機能を足すときは、**別ファイルに外付けする**。同じファイルに書き足すと差分が読めなくなり、既存データを壊す危険も上がる。
- ドキュメントの数字（分野数・単元数・問題数・図版数）は、分野を足すたびにその場で直す。「18分野」のまま放置したら、3ファイル20か所に散らばった。
  **数えられる数字は検証に入れる**（`tools/check/docs.js` が README・設計書・再現プロンプトの表を実データと突き合わせ、
  「最終更新」の日付の上げ忘れも見る）。
- **検証スクリプト自身も検証する。** 読み物の検証が、2分野とも1分野目のデータを読んでいた（一時ファイル名をパスの末尾から作っていて衝突した）。データを読むときは一時ファイルを作らず `new Function` で評価する。足したあと、**2つ通して違う結果が出る**ことを確かめる。
- ドキュメントに「数を揃える」と書いただけでは揃わない。`?v=` の6枚そろえは手順書にも README にも書いたのに、また4枚が取り残された。**数えられる不整合は検証スクリプトに入れる**（`tools/check/ver.js` が `?v=` と `CACHE` の番号を照合する）。
