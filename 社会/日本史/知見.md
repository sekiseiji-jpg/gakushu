# 日本史マスター 開発で得た知見

最終更新: 2026-10-19

作っている途中で実際にぶつかった問題と、その原因・対処のまとめです。各項目は「症状 → 原因 → 対処」の順。
同じ構成（素の HTML/JS の PWA）の別アプリにも使えるものが多いはずです。

---

## 1. クイズの設計

### 1.1 選択肢を一律にシャッフルすると設問が壊れる
- **症状**: 年代配列問題（「Ⅰ−Ⅱ−Ⅲ」「Ⅱ−Ⅰ−Ⅲ」…）をシャッフルしたら、「古いものから順に」という設問に対して選択肢の並びが意味をなさなくなる。組合せ問題（`a・c` `a・d` `b・c` `b・d`）も同じ。
- **原因**: センター試験形式の選択肢は、**並び自体が設問の一部**になっている形式がある。単語4択と同じ扱いにしてはいけない。
- **対処**: `const canShuffle = S.set.shuffle && (q.type === 'sel' || q.type === 'src');` と形式で分岐。正解の表示位置は `session.cur.idx.indexOf(q.a)` で毎回求める（`q.a` は元の並びのインデックスのまま保持する）。

### 1.2 絞り込みチップで「0問」になる事故
- **症状**: 分野チップを全部外すと、出題対象0問で「出題開始」が無反応になる。
- **対処**: トグルした結果 `Set` が空になったら、その場で全選択に戻す。あわせて「出題対象 N問」を常時表示して、押した結果が即わかるようにした。

### 1.3 問題の `id` は学習記録の主キー
- 誤答数・保存問題はすべて `q.id` で記録している。あとから問題文を修正するのは安全だが、**`id` を変えると過去の記録が迷子になる**。問題を削除する場合も `QUIZ.find()` が `undefined` を返すので、記録表示側は必ず `.filter(Boolean)` する（`#stat-weak` と保存タブで実際に必要だった）。

### 1.4 二重回答の防止
- 回答後も選択肢がクリックできると正解数が二重に増える。`b.disabled = true` だけでなく `session.cur.answered` フラグでも弾く二段構えにした。

## 2. データ作成

### 2.1 大量の日本語をヒアドキュメントで書くときは必ず検証する
- **症状**: 長い日本語データを書いているうちに、本文中に `village`・`private`・`большой` といった**別言語の単語が混入**した（生成の揺れ）。見た目では気づきにくい。
- **対処**: 書き終えるたびに `grep -nP '[a-zA-Z]{3,}|[\x{0400}-\x{04FF}]' data-*.js` で日本語以外の連続文字を洗い出し、該当行を目視する。コード部分（`id:` や `module.exports`）は除外して絞りこむ。
- **教訓**: データファイルは「構文が通る」だけでは不十分。**中身の言語そのものを機械的にチェックする**工程を入れる。
- **再発した**: 問題を97問から203問へ増やす作業でも、`market が開かれ`・`氏single単位に` という形で同じ混入が起きた。長い日本語を大量に書くときは必ず起こると考えて、チェックを毎回回す。

### 2.1b 言語チェックは grep ではなく Node で「本文フィールドだけ」を見る
- **失敗**: `grep -nP '[a-zA-Z]{3,}'` で探したが、①macOS 標準の BSD grep には `-P` がなくスクリプトから呼ぶとエラーになる ②`id:'q-heian-9'` や `type:'sel'` などコード部分が大量に引っかかって本物の混入が埋もれる、という二重の問題が出た（378件中、本物は2件だけだった）。
- **対処**: データを Node で `require()` し、`q` / `src` / `exp` / `choices` という**本文フィールドだけ**を取り出して正規表現をかける小さなスクリプトにした。`GHQ`・`GNP` など正当な欧字略語は許可リストに入れる。これで誤検出がゼロになり、混入2件だけがきれいに出た。
- **教訓**: 検査対象を「ファイル全体のテキスト」ではなく「意味のあるフィールド」に絞ると、ノイズが消えて検査が実用になる。構造化データは構造を使って検査する。

### 2.4 データ追加はチェックスクリプトを先に作る
- 203問への増量では、追記 → 検証 → 次の追記、を4回くりかえした。先に検証スクリプト（件数・時代別内訳・id重複・正解インデックスの範囲・選択肢数・形式別の件数・言語チェック）を1本用意しておくと、各ラウンドの終わりに1コマンド叩くだけで済む。
- 検証のために末尾の `];` と `module.exports` を一時的に外しておき、チェック時だけ連結して読ませる方式にすると、追記のたびにファイル末尾を編集し直さずに済んだ。

### 2.5 形式のカバー率は時代ごとに数える
- 全体の形式別件数だけ見ていると、「特定の時代に年代配列問題が1問もない」といった偏りに気づけない。時代×形式のクロス集計を出すようにしたところ、実際に穴が見つかった。
- なお旧石器・縄文時代だけは史料問題を置いていない。文字史料のない時代であり、史料読解の設問が成り立たないため。**「全時代で形式をそろえる」という機械的な目標より、内容として成立するかを優先する**。

### 2.2 Node で読めるようにしておくと検証が一瞬
- 各データファイルの末尾に `if (typeof module !== 'undefined') { module.exports = { ERAS }; }` を置くだけで、ブラウザ用の素の JS のまま `node -e "require('./data-eras.js')"` で件数・重複ID・正解インデックスの範囲を検証できる。ビルドツールを入れずに済む。

### 2.3 ヒアドキュメントは必ずクォートする
- `cat > file <<'JSEOF'` のようにデリミタをシングルクォートで囲む。囲まないと `$` や `` ` `` がシェルに展開され、JS のテンプレートリテラルや `${}` が壊れる。

## 3. 見た目

### 3.1 ダークモードで「ブランド色の上の白文字」が読めなくなる
- **症状**: ライトでは濃い赤 `#9b2d20` に白文字で問題ないが、ダークでは `--primary` を明るい朱色 `#e0705f` にしたため、同じ白文字だとコントラスト比が 2.6 程度まで落ちた。
- **原因**: `--primary` を「アクセント色」と「背景色」の両方に使い回していた。明るさを反転させると、その上の文字色も反転させる必要がある。
- **対処**: ①ダークでは `--primary-text` を**暗い色**（`#2a1512`）にする。②ヘッダーだけは別変数 `--header-bg` / `--header-fg` を用意し、明暗どちらでも「濃い赤＋白」で固定する。背景として使う色と、文字・線として使う色は変数を分けるのが安全。

### 3.2 ダークの指定は2か所に書く
- 設定で明暗を強制切替できるようにすると、`@media (prefers-color-scheme: dark)` だけでは足りない。`:root:not([data-theme="light"])` 付きのメディアクエリ版と、`:root[data-theme="dark"]` の直接指定版の**両方**が要る。片方を更新し忘れると、設定でダークにしたときだけ色が古いままになる。

### 3.3 `color-mix()` にはフォールバックを
- 時代ごとの色からグラデーションを作るのに `color-mix(in srgb, var(--ec) 60%, #000)` を使った。未対応ブラウザでは**宣言ごと無視されて背景が透明**になり、白背景に白文字で消える。直前に `background: var(--ec);` を書いて上書きさせる。

### 3.4 文字サイズ設定は `body` の `font-size` に当てる
- `rem` 基準（`html` の font-size）を動かすと、`rem` で書いた padding やボーダー半径まで一緒に拡大してレイアウトが崩れる。`body { font-size: var(--fs) }` にして、各要素は `em` / `rem` 混在のまま触らないほうが安定した。

### 3.5 横スクロールするタブは `scrollbar-width: none` とセットで
- タブが多いと横スクロールになる。`::-webkit-scrollbar { display: none }` と `scrollbar-width: none` を両方書かないと、スマホで下端にスクロールバーの帯が出る。狭い画面ではアイコンだけにして（`.tab .tl { display: none }`）、選択中のタブだけラベルを出すと収まりがよい。

## 4. 動作確認

### 4.1 スクリーンショットは1手遅れて見えることがある
- **症状**: ブラウザ操作 → 即スクリーンショット、で「クリックが効いていない」「画面が真っ白」に見えた。
- **実際**: DOM を調べると処理は完了していた。描画やキャプチャのタイミングの問題で、`.panel.active` のフェードイン（`animation: fade .22s`）の途中が写っていただけだった。
- **対処**: 「効いていない」と判断する前に **DOM を直接確認する**（`document.getElementById('q-feedback').innerHTML` など）。見た目を確かめたいときは 1 秒待ってから撮る。
- **教訓**: 症状を見た瞬間にコードを疑わず、まず状態を観測する。

### 4.2 グローバル関数を呼べるようにしておくとテストが速い
- `app.js` を素のスクリプト（モジュールではない）にしているので、`openEra('meiji','words')` や `startQuiz()` をブラウザのコンソールから直接呼べる。各画面を手でクリックして辿らずに、史料問題・年代配列問題など特定の状態を一発で再現できた。

## 5. PWA

### 5.1 更新のたびに `CACHE` と `?v=` を同じ番号で上げる
- `index.html` から `app.js?v=1` のように版番号付きで読むことで、新しい HTML と古い JS が混ざるのを防ぐ。**ローカル確認のときも上げる**（上げないとブラウザが古い CSS を使い続け、「直したのに変わらない」と勘違いする）。

### 5.2 オフライン前提のアプリでは外部 CDN を使わない
- このアプリは外部 API もフォントの CDN も使っていないので、Service Worker に列挙した10ファイルだけで完全に動く。学習アプリは電車の中など回線のない場所で使われるため、この制約は最初から守るほうが楽。

### 5.3 localStorage は1キーにまとめる
- 設定・記録・保存をキーごとに分けると、リセットやマイグレーションのたびに取りこぼす。`nihonshi.v1` の1キーに全部入れ、`load()` で `defaults` とマージする形にすると、**あとから項目を足しても既存ユーザーが壊れない**（実際に開発中「学習した日数」用の `days` を後から追加したが、何もせずに動いた）。
