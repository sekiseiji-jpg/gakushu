# 学習アプリ群 設計書（20分野共通）

最終更新: 2026-10-22

## 1. 概要

高校の5教科20分野を、単元ごとの解説とクイズで学べるアプリ群。社会・理科・数学・国語・英語は大学入学共通テストの出題形式に、漢検2級と英検2級は検定の出題に合わせている。
もともと社会（日本史・世界史・地理・政治・経済・倫理）のために作った構造とエンジン（`app.js`）を、理科4分野・数学3分野・国語4分野・英語4分野でもそのまま使っている（合計20分野）。
国語の「古典文学」「近現代文学」と、英語の「英米文学」だけはクイズのない読み物で、このエンジンを使わず専用のつくりになっている。
読み物の `app.js` は3分野で同一のファイルで、違いは `data-works.js` の `APP`（単位・キャッシュ名・本文の版・対照の注記）と、作品ごとの `rich`／`yakuLabel` だけに置いてある。
作家紹介は `data-authors.js`（`AUTHORS`）、語注は `data-notes.js`（`NOTES`）を置いた分野にだけ出る。app.js はデータが無ければ画面も要素も作らないので、他の分野は何も変わらない。
このファイルは**20分野に共通する内部構造**を説明する（社会のフォルダに置いてあるのは、ここから始めたという経緯のため）。

HTML / CSS / JavaScript だけで動き、ビルド不要・外部 API なし。PWA としてホーム画面に追加でき、完全にオフラインで使える。

- 階層: `学習アプリ/index.html`（教科）→ `<教科>/index.html`（分野）→ 各アプリ
- ローカル起動: `学習アプリ/start.command`（Mac）／`start.bat`（Windows） → http://localhost:8771/
- 各アプリは単独でも起動できる（下表のポート）

## 3. 1つのエンジンを20分野で共有するしくみ

画面の動作（`app.js`）は20分野で共通で、分野ごとの違いはすべて `data-units.js` 冒頭の `APP` オブジェクトに切り出してある。

```js
const APP = {
  key: 'chiri.v1',             // localStorage のキー
  title: '地理マスター',
  icon: '🗺️',
  unitWord: '分野',             // 「時代」「分野」「単元」
  listWord: '統計',             // 「年表」「統計」「公式」「データ」「文法」「句法」など
  leadUnits: '…',               // 一覧画面の説明文
  searchPlaceholder: '…',
  cats: ['自然', '産業', '人口・都市', '地誌'],       // クイズの分野区分（4つ）
  typeLabels: { sel:'正誤判定', cmb:'組合せ', ord:'順位配列', src:'資料読取' },
  typeNotes: ['…'],             // 出題形式の説明（クイズ設定画面）
  wordsHeads: ['重要用語', 'まちがえやすい区別'],     // 用語タブの2見出し（省略可）
  kinds: { word:'用語', person:'区別', event:'公式' }, // 検索結果の種別ラベル（省略可）
};
```

`wordsHeads` と `kinds` は省略できる。省略すると `app.js` の既定値（`['重要用語','おもな人物']` と `{word:'用語',person:'人物',event:'できごと'}`）になる。
社会5分野は省略している（倫理は生成分野だが、社会の既定語のままでよい）。用語タブの名前は、雛形元の4分野（日本史・世界史・地理・政治・経済。地理だけ「用語・事例」）は `index.html` に直接入っており、生成した15分野は `apps.json` の `wordsTab` から差し替える。

`app.js` の `applyBranding()` が起動時にこれを画面へ反映する（タイトル、タブ名、サブタブ名、見出し、プレースホルダー）。
生成時にしか使わない値（タブの絵文字 `listIcon`、テーマタブの呼び名 `themeWord`、用語タブ名 `wordsTab`、配色20色、ポート）は `tools/tpl/apps.json` にある。
**分野を1つ増やすときに `app.js` を触る必要はない。**

## 4. データ構造

### 4.1 `UNITS`（単元データ）

```js
{
  id: 'kikou',                   // 一意のID。クイズの era と対応
  name: '気候', yomi: 'きこう',
  span: '大気大循環・ケッペンの気候区分',  // 表示用のサブタイトル
  n0: 300, n1: 399,              // 並べ替え用の範囲（歴史は西暦、ほかは分野番号）
  icon: '☀️', color: '#039be5',  // 単元色。CSS 変数 --ec に流しこむ
  catch: '一行キャッチコピー',
  summary: ['段落1', '段落2', …],
  sections: [{ t:'見出し', items:[{ h:'小見出し', b:'本文' }, …] }, …],
  keywords: [{ w:'用語', y:'よみ', d:'説明' }, …],
  people:   [{ n:'人名・区別', y:'よみ', d:'説明' }, …],
  events:   [{ n:301, y:'表示用', t:'項目', d:'補足' }, …],   // n が並べ替えキー
  topics:   [{ t:'題', lead:'リード', body:['段落', …] }, …]
}
```

同じ器を、教科によって意味を変えて使っている。**フィールドを増やさずに20分野を通すのが方針。**

| フィールド | 社会（歴史・政経・倫理） | 地理 | 理科・数学 | 国語 | 英語 |
|---|---|---|---|---|---|
| `events` | 年表（`n` は西暦。紀元前はマイナス） | 統計データ（`n` は分野番号×100＋通し番号） | 重要公式・データ | 重要語・文法・句法 | 重要表現・文法事項 |
| `people` | 人物（倫理は思想家） | まぎらわしい用語の対比 | まちがえやすい区別 | まちがえやすい区別 | まちがえやすい区別 |

### 4.2 単語帳（`APP.cardMode`）

語を覚える分野では、一覧タブが単語帳になる。`APP.cardMode` を立てた分野にだけ、
「意味をかくす」というボタンが出る。押すと説明（`events[].d`）が帯で隠れ、
その行をおすと一つずつ出る。赤シートと同じ使い方である。

```js
const APP = { …, cardMode: true };
```

- 立てていない分野では、ボタンそのものが作られないので何も変わらない（13.3 と同じ考え方）。
- 隠す・出すの状態は `S.set.mask` に持ち、分野ごとの localStorage に残る。
- いま立てているのは **英検2級**（単語1500語）と **漢検2級**（よく間違える語1500 ＋ 配当漢字185）の二つ。

### 4.3 発音記号と読み上げ（`APP.speak` ／ `events[].p`）

語を覚える分野では、語の横に発音記号を出し、🔊 を押すと端末の音声で読み上げる。

```js
const APP = { …, speak: 'en-US' };                       // この分野だけ 🔊 を出す
{ n: 100, y: '名詞', t: 'relative', p: '/ˈrelətɪv/', d: '親類、親戚。…' }
```

- `APP.speak` を立てていない分野では、ボタンを作らないので何も変わらない（4.2 と同じ考え方）。
- 音声は端末に入っているものを使う（Web Speech API）。**ネットにはつながらないので、オフラインでも鳴る。**
- その言語の声が端末に無いときは、別の言語の声で読まれてしまう。黙って変な音を出すより、
  一覧に「その言語の音声が入っていません」と出す。
- 単語帳で意味をかくしているとき、🔊 を押しても意味は開かない（`stopPropagation`）。
- いま立てているのは **英検2級**（1500語すべてにアメリカ発音の発音記号）。

### 4.4 `FIGS`（説明にそえる図・表・地図・写真）

単元データとは別のファイル `data-figs.js` に置く。`UNITS` は大きいので、図版を足すために触らなくて済むようにした。

```js
const FIGS = {
  kikou: [
    { at: 'ov',   k: 'table', t: '見出し', cap: '説明',
      head: ['列1', '列2'], rows: [['…', '…'], …] },
    { at: 'sec1', k: 'svg',   t: '見出し', cap: '説明', svg: '<svg viewBox="…" role="img">…</svg>' },
    { at: 'sec2', k: 'map',   t: '見出し', cap: '説明', svg: '<svg …>…</svg>' },
    { at: 'ov',   k: 'photo', t: '見出し', cap: '説明',
      src: 'img/xxx.jpg', credit: 'ウィキメディア・コモンズ「…」（Public domain）' },
  ],
};
```

- `at`… 出す場所。`'ov'` は概要タブの要約の下、`'secN'` は詳細タブの第N節の下（0から数える）。
- `k`… 種類。`table`（表）／`svg`（図）／`map`（地図）／`photo`（写真）。
- 図と地図の SVG は色を直書きせず、`var(--primary)` `var(--text)` `var(--muted)` `var(--surface)` `var(--border)` などの CSS 変数で塗る。こうすると明るい画面・暗い画面・セピアのどれでも読める。`viewBox` と `role="img"` は必須。
- 写真は Public domain・CC0・No restrictions のものだけ。1枚130KB以下に圧縮し、`credit` に出どころを書く。
- 単元ごと・分野ごとに有無は自由。ファイルが無い分野があっても動く（`figsOf()` が空配列を返す）。

検証は `node tools/check/figs.js [分野 …]`。単元IDと `at` の行き先が実在するか、表の列数がそろっているか、SVG が閉じているか・色を直書きしていないか、写真があって大きすぎないか・権利表示が正しいか、図の中も含めて日本語以外の文字がまぎれていないかを見る。

### 4.5 `QUIZ`

```js
{
  id: 'q-kikou-4',   // 一意。学習記録のキーなので変更しない
  era: 'kikou',      // UNITS の id
  type: 'src',       // sel / cmb / ord / src
  cat: '自然',        // APP.cats のいずれか
  lv: 2,             // 1=基本 2=標準 3=やや難（★の数）
  q: '設問文（\n で改行可）',
  src: '史料・資料本文',   // type:'src' のときのみ
  choices: ['①の文', …],  // ord は6択、それ以外は4択
  a: 0,              // 正解のインデックス（choices の元の並び順）
  exp: '解説'
}
```

**出題形式は共通テストの定番に合わせている。** 呼び名は 3章の表のとおり分野で変わるが、データ構造と判定ロジックは共通。

形式の比率は、倫理以降に作った15分野では `sel` 半分・`cmb` `ord` `src` 各6分の1（180問なら 90・30・30・30）に統一している。
社会の最初の4分野（日本史・世界史・地理・政治・経済）は、作りながら形式を増やしたため比率が揃っていない（日本史は203問で `sel` 112・`cmb` 37・`ord` 31・`src` 23）。

- `cmb` の選択肢は `['a・c','a・d','b・c','b・d']` で固定。したがって**正しい文は {a,b} から1つ、{c,d} から1つ**でなければならない。
  先に作った社会4分野（日本史の一部・世界史・地理・政治経済）だけは `['a・b','a・d','b・c','c・d']` を使っている。こちらは**正しい文が2つ・誤りが2つ**で、上の規則は当てはまらない。検証は選択肢の並びを見て切り替える。
- `ord` の選択肢は `Ⅰ−Ⅱ−Ⅲ` 〜 `Ⅲ−Ⅱ−Ⅰ` の6通りを固定の順で並べる。

### 4.6 `THEMES`

`{ id, icon, title, color, lead, steps: [{ era:'表示用のラベル', t, b }, …] }`。
`steps[].era` は `UNITS.id` ではなく「飛鳥・奈良」「気候」のような表示用の文字列（複数単元にまたがるため）。

## 7. クイズの実装で注意している点

1. **選択肢のシャッフルは `sel` と `src` のみ。** `ord`（Ⅰ−Ⅱ−Ⅲ）と `cmb`（a・c など）は選択肢の並び自体が設問の一部なので、シャッフルすると設問が壊れる。表示順は `session.cur.idx` に持ち、正解の表示位置は `idx.indexOf(q.a)` で求める。
2. **絞り込みチップが空にならないようにする。** トグルの結果 `Set` が空になったら、その場で全選択に戻す。
3. **二重回答の防止。** `b.disabled = true` に加えて `session.cur.answered` フラグでも弾く。
4. **問題の `id` は学習記録の主キー。** あとから変えない。削除に備えて参照側は `.filter(Boolean)` する。
5. **シャッフルしない形式は正解位置が偏る。** `cmb` / `ord` は形式ごとに正解インデックスを集計し、最大でも5割を超えないようにする（偏りの直し方は `知見.md` 2.8 / 8.3）。

| スクリプト | 調べること |
|---|---|
| `chk.js` | 1分野の件数・ID・正解インデックス・分野区分・言語（上の7点） |
| `figs.js` | 図・表・地図・写真（単元IDと出す場所、表の列数、SVGの閉じと色の直書き、写真の権利と大きさ、図の中も含めた言語） |

**データを書いたら必ず検証する。** 確かめるのは次の7点。

1. 総数と単元別の内訳（各単元12問以上）
2. `id` の重複がないこと（単元・問題とも）
3. すべての問題で `0 <= a < choices.length`
4. `ord` は6択、それ以外は4択
5. `type:'src'` の問題に `src` 本文があること
6. `era` が `UNITS` に実在すること
7. 本文（`q` / `src` / `exp` / `choices`）に日本語以外の語が混入していないこと

7はファイル全体を `grep` すると `id:'q-kikou-4'` のようなコード部分が大量に引っかかるので、Node で読んで**本文フィールドだけ**を調べる。
**基準は教科によって変える。**

| 教科 | 検出する語 | 理由 |
|---|---|---|
| 社会・国語 | 2文字以上のラテン文字（`GDP` `SNS` などは許可リスト） | `village` `market` のような混入を拾う |
| 理科・数学 | 4文字以上で、かつ「全部小文字」か「先頭だけ大文字」の語 | `mg` `ZnSO` `IBLsinθ` のような化学式・数式を除く |
| 英語 | ラテン文字は検出しない。キリル文字・ハングル・アラビア文字のみ | 例文が英語なので、ラテン文字を疑うと全部ひっかかる |

あわせて `cmb` の正解が `/^[ab]・[cd]$/` に一致するか、解説に書いた番号と `a` が一致するか、形式ごとの正解位置が偏っていないかも機械的に確かめる（経緯は `知見.md` 2.6〜2.8）。

> 現在の `check.sh` は冒頭にパスを直書きしており、教科の分岐も理科ぶんしか入っていない（`知見.md` 11.1 / 11.2）。作り直すときは、パスをスクリプトの位置から求め、教科 → 基準の対応を表としてスクリプト内に持たせる。

## 11. オフライン対応と更新手順

各アプリと、ポータル（`学習アプリ/sw.js`）がそれぞれ Service Worker をもつ。いずれもネット優先・失敗したらキャッシュ。
Service Worker のスコープは置かれたディレクトリなので、アプリのフォルダは各アプリの SW が、それ以外はポータルの SW が担当する。ポータル側のキャッシュ一覧にアプリのファイルは含めない。

**更新手順**: ファイルを変えたら、そのアプリの `sw.js` の `CACHE` と `index.html` の `?v=` を**同じ番号で**上げる。ローカル確認のときも上げる。
索引（`search-index.js`）を作り直したときは、**ポータルと教科ページ5枚の `?v=` を同じ番号に揃え**、ポータルの `sw.js` の `CACHE` も上げる（現在は 15）。

## 12. 内容を増やすとき

- **単元を足す**: `UNITS` に追加するだけ。カード一覧・年表・検索インデックス・クイズの絞り込みチップはすべて `UNITS` から自動生成される。終わったら `mkindex.js`。
- **問題を足す**: `QUIZ` に追加。`id` は重複させない。`ord` は6択、`cmb` は `['a・c','a・d','b・c','b・d']` で統一する。

- **図・表・写真を足す**: その分野の `data-figs.js` に `単元id: [ … ]` を書く。`UNITS` には触らない。終わったら `node tools/check/figs.js <教科>/<分野>`。写真は Public domain・CC0・No restrictions のものだけを、130KB以下に縮めて `img/` に置く。
- **読み物の作品を足す**: `data-works.js` の `WORKS` に1件足し、`text/<作品id>/NN.js` を章の数だけ置く。文豪を足すときは `data-authors.js` の `AUTHORS` と `authors/<文豪id>.jpg`、語注を足すときは `data-notes.js` の `NOTES`（キーは「作品id/章番号」）。終わったら `node tools/check/reader.js`。
- **教科を足す**: 教科フォルダと教科ページ（`data-subject` / `data-base` を持つ分野選択ページ）を作り、ポータルにカードを足す。`mkindex.js` の `SUBJECTS` に教科名を加える。

### 13.1 データ構造

```js
const APP = { key, title, icon, unitWord, cacheName, textVer, … };
const WORKS = [{
  id: 'genji', title: '源氏物語', author: '紫式部', yomi: 'げんじものがたり',
  rich: true,            // 原文と現代語訳を切り替えられるか
  yakuLabel: '与謝野訳',  // 訳の呼び名
  lead: '…', summary: ['…'],
  maki: [{ no: 1, t: '桐壺', sum: '巻の要約' }, …],
}];
const NOTES = { 'alice/1': [{ w: 'peep', d: 'ちらりとのぞく' }] };   // 英米文学のみ（data-notes.js）
const AUTHORS = [{            // 近現代文学のみ
  id: 'soseki', name: '夏目漱石', yomi: '…', born: 1867, died: 1916,
  from: '江戸（東京）', photo: 'authors/soseki.jpg',
  bio: ['略歴の段落'], style: ['作風と主張'], works: ['ほかの代表作'],
}];
```

本文は `text/<作品id>/NN.js` に分け、開いた巻だけを `<script>` の差しこみで読む。
各ファイルは `TEXT(巻番号, { y: [原文の段落], g: [訳の段落] })` を呼ぶだけ。85巻・214章を一度に読むと重すぎるため。

### 13.2 段落の種類は先頭1文字で表す

段落の文字列は、先頭の1文字が種類を表す。

| 先頭 | 種類 |
|---|---|
| `p` | 地の文 |
| `v` | 韻文・字下げ |
| `c` | 右寄せ（署名など） |
| `h` | 小見出し |
| `w` | 和歌（古典文学の原文のみ） |

**大文字にすると、その前に1行ぶんの空きが入る。** 空行を別の要素として持たずに済ませるための約束。

### 13.3 ふりがな

青空文庫の記法 `｜漢字《よみ》` をデータにそのまま残し、表示するときに `ruby()` が `<ruby>` へ組み立てる。
データを見れば元の表記がわかるので、取りこみ直しや突き合わせがしやすい。
外字 `※［＃…、面-区-点］` は取りこみの時点で実際の文字に直しておく。

### 13.4 読み上げ

章の本文を、端末に入っている音声で読む。`#maki-speak` の「▶ 読み上げ」と速さの選択で操作する。

- **長い段落は文ごとに切って渡す。** 一度に長い文を渡すと、途中で切れてしまう端末がある。
- ルビの `<rt>` はたどらない。たどると親文字と読みが二重に読まれる（「薔薇ばら」）。
- 訳と原文で言語が違う分野がある。`APP.speakLang`（既定 `ja-JP`）と `APP.genbunLang` で分け、
  対照表示では段落ごと（`.gen` は原文の言語、`.yak` は訳の言語）に切り替える。
- 章を変えたとき、画面を離れたときは止める。いま読んでいる段落には下地を敷く（`.sp-now`）。
- 音声はネットを使わないので、保存した本文と同じくオフラインでも鳴る。

### 13.5 対照表示（`maki[].aligned`）

原文と訳を一段ずつ並べて出す。`aligned: true` を立てた章だけボタンが出る。
**訳の段落数と原文の段落数が同じで、同じ順に並んでいることが条件**で、立てていない章では
`has(m, 'taisho')` が偽になり、ボタンそのものが隠れる。
`rich` の分野では訳にも種類の印（先頭1文字）がついているので、落としてからルビを組む。

いま立てているのは **不思議の国のアリス**（全12章806段落）だけである。

### 13.6 本文のキャッシュは版と切り離す

`sw.js` はキャッシュを2つ持つ。

```js
const CACHE = 'kotenbungaku-v8';      // 骨組み。版を上げると捨てる
const TEXTS = 'kotenbungaku-text';    // 本文。版を上げても残す
```

`/text/` を含む URL だけ `TEXTS` に入れる。こうすると、アプリを更新しても**まとめて保存した本文が消えない**。

### 13.7 語注（英米文学だけ）

英語の原文を読むには、語の助けが要る。語注は `data-notes.js` に外付けし、キーは「作品id/章番号」。

```js
const NOTES = {
  'alice/1': [ { w: 'waistcoat', d: 'チョッキ（胴着）' }, … ],
};
```

- 出る場所は、章のあらすじの下・本文の上。`app.js` は `#maki-notes` という要素と `NOTES` の両方がある分野だけ描くので、他の読み物は何も変わらない。
- 挙げるのは、英検2級の語彙をこえる語と、語の形は易しいがその章で特別な意味に使われている語（`tale` と `tail` の取りちがえなど）。
- **見出しは、その章の原文に実在する語でなければならない。** `tools/check/reader.js` が原文と突き合わせる。記憶で書くと必ず入っていない語がまぎれる（最初に書いた122件のうち18件が実在しなかった）。

### 13.8 権利

本文はいずれも保護期間が満了したもの、または CC0 のものだけ。巻ごとの要約と作品解説、文豪の紹介文、語注はすべて書き下ろし。
肖像写真は Public domain・CC0・No restrictions のものだけを使い、出どころを添えている。

英米文学の原文はプロジェクト・グーテンベルクから取り、落とす前に各作品の権利表示を機械的に確かめている。
日本語訳は青空文庫の目録の著作権フラグで判断する。訳者の没年だけでは決まらない（旧法の保護期間50年が
2018年の延長より前に満了していれば、延長の対象にならない）ので、目録に当てるのが唯一の確実な手順である。
あわせて目録の**文字遣い種別**も見る。旧字旧仮名の訳は現代の読者には読みにくいので、学習の助けとしては使わず、
「明治の訳」のように何であるかを明示して併載する。
