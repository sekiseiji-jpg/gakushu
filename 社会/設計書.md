# 学習アプリ群 設計書（18分野共通）

最終更新: 2026-10-20

## 1. 概要

高校の5教科18分野を、単元ごとの解説と大学入学共通テスト形式のクイズで学べるアプリ群。
もともと社会（日本史・世界史・地理・政治・経済・倫理）のために作った構造とエンジン（`app.js`）を、理科4分野・数学3分野・国語4分野・英語3分野でもそのまま使っている（合計19分野）。
国語の「古典文学」だけはクイズのない読み物で、このエンジンを使わず専用のつくりになっている（`国語/古典文学/app.js`）。
このファイルは**18分野に共通する内部構造**を説明する（社会のフォルダに置いてあるのは、ここから始めたという経緯のため）。

HTML / CSS / JavaScript だけで動き、ビルド不要・外部 API なし。PWA としてホーム画面に追加でき、完全にオフラインで使える。

- 階層: `学習アプリ/index.html`（教科）→ `<教科>/index.html`（分野）→ 各アプリ
- ローカル起動: `学習アプリ/start.command`（Mac）／`start.bat`（Windows） → http://localhost:8771/
- 各アプリは単独でも起動できる（下表のポート）

## 3. 1つのエンジンを18分野で共有するしくみ

画面の動作（`app.js`）は18分野で共通で、分野ごとの違いはすべて `data-units.js` 冒頭の `APP` オブジェクトに切り出してある。

```js
const APP = {
  key: 'chiri.v1',             // localStorage のキー
  title: '地理マスター',
  icon: '🗺️',
  unitWord: '分野',             // 「時代」「分野」「単元」
  listWord: '統計',             // 「年表」「統計」「公式」「データ」「文法」「句法」など
  leadUnits: '…',               // 一覧画面の説明文
  searchPlaceholder: '…',
  cats: ['自然', '産業', '人口・都市', '地誌'],       // クイズの分野区分（4つ）
  typeLabels: { sel:'正誤判定', cmb:'組合せ', ord:'順位配列', src:'資料読取' },
  typeNotes: ['…'],             // 出題形式の説明（クイズ設定画面）
  wordsHeads: ['重要用語', 'まちがえやすい区別'],     // 用語タブの2見出し（省略可）
  kinds: { word:'用語', person:'区別', event:'公式' }, // 検索結果の種別ラベル（省略可）
};
```

`wordsHeads` と `kinds` は省略できる。省略すると `app.js` の既定値（`['重要用語','おもな人物']` と `{word:'用語',person:'人物',event:'できごと'}`）になる。
社会5分野は省略している（倫理は生成分野だが、社会の既定語のままでよい）。用語タブの名前は、雛形元の4分野（日本史・世界史・地理・政治・経済。地理だけ「用語・事例」）は `index.html` に直接入っており、生成した14分野は `apps.json` の `wordsTab` から差し替える。

`app.js` の `applyBranding()` が起動時にこれを画面へ反映する（タイトル、タブ名、サブタブ名、見出し、プレースホルダー）。
生成時にしか使わない値（タブの絵文字 `listIcon`、テーマタブの呼び名 `themeWord`、用語タブ名 `wordsTab`、配色20色、ポート）は `tools/tpl/apps.json` にある。
**分野を1つ増やすときに `app.js` を触る必要はない。**

## 4. データ構造

### 4.1 `UNITS`（単元データ）

```js
{
  id: 'kikou',                   // 一意のID。クイズの era と対応
  name: '気候', yomi: 'きこう',
  span: '大気大循環・ケッペンの気候区分',  // 表示用のサブタイトル
  n0: 300, n1: 399,              // 並べ替え用の範囲（歴史は西暦、ほかは分野番号）
  icon: '☀️', color: '#039be5',  // 単元色。CSS 変数 --ec に流しこむ
  catch: '一行キャッチコピー',
  summary: ['段落1', '段落2', …],
  sections: [{ t:'見出し', items:[{ h:'小見出し', b:'本文' }, …] }, …],
  keywords: [{ w:'用語', y:'よみ', d:'説明' }, …],
  people:   [{ n:'人名・区別', y:'よみ', d:'説明' }, …],
  events:   [{ n:301, y:'表示用', t:'項目', d:'補足' }, …],   // n が並べ替えキー
  topics:   [{ t:'題', lead:'リード', body:['段落', …] }, …]
}
```

同じ器を、教科によって意味を変えて使っている。**フィールドを増やさずに18分野を通すのが方針。**

| フィールド | 社会（歴史・政経・倫理） | 地理 | 理科・数学 | 国語 | 英語 |
|---|---|---|---|---|---|
| `events` | 年表（`n` は西暦。紀元前はマイナス） | 統計データ（`n` は分野番号×100＋通し番号） | 重要公式・データ | 重要語・文法・句法 | 重要表現・文法事項 |
| `people` | 人物（倫理は思想家） | まぎらわしい用語の対比 | まちがえやすい区別 | まちがえやすい区別 | まちがえやすい区別 |

### 4.2 `QUIZ`

```js
{
  id: 'q-kikou-4',   // 一意。学習記録のキーなので変更しない
  era: 'kikou',      // UNITS の id
  type: 'src',       // sel / cmb / ord / src
  cat: '自然',        // APP.cats のいずれか
  lv: 2,             // 1=基本 2=標準 3=やや難（★の数）
  q: '設問文（\n で改行可）',
  src: '史料・資料本文',   // type:'src' のときのみ
  choices: ['①の文', …],  // ord は6択、それ以外は4択
  a: 0,              // 正解のインデックス（choices の元の並び順）
  exp: '解説'
}
```

**出題形式は共通テストの定番に合わせている。** 呼び名は 3章の表のとおり分野で変わるが、データ構造と判定ロジックは共通。

形式の比率は、倫理以降に作った14分野では `sel` 半分・`cmb` `ord` `src` 各6分の1（180問なら 90・30・30・30）に統一している。
社会の最初の4分野（日本史・世界史・地理・政治・経済）は、作りながら形式を増やしたため比率が揃っていない（日本史は203問で `sel` 112・`cmb` 37・`ord` 31・`src` 23）。

- `cmb` の選択肢は `['a・c','a・d','b・c','b・d']` で固定。したがって**正しい文は {a,b} から1つ、{c,d} から1つ**でなければならない。
  先に作った社会4分野（日本史の一部・世界史・地理・政治経済）だけは `['a・b','a・d','b・c','c・d']` を使っている。こちらは**正しい文が2つ・誤りが2つ**で、上の規則は当てはまらない。検証は選択肢の並びを見て切り替える。
- `ord` の選択肢は `Ⅰ−Ⅱ−Ⅲ` 〜 `Ⅲ−Ⅱ−Ⅰ` の6通りを固定の順で並べる。

### 4.3 `THEMES`

`{ id, icon, title, color, lead, steps: [{ era:'表示用のラベル', t, b }, …] }`。
`steps[].era` は `UNITS.id` ではなく「飛鳥・奈良」「気候」のような表示用の文字列（複数単元にまたがるため）。

## 6. 画面

- **単元タブ**: カード一覧 → 詳細（6つのサブタブ: 概要／詳細／用語・人物／年表・統計／トピック／クイズ）。`◀ ▶` で前後の単元へ（サブタブは維持）。ヘッダー左の `◀` で分野一覧へもどる。
- **年表・統計タブ**: 全単元を通しで一覧。単元チップで絞り込み、テキスト検索で該当語を `<mark>` でハイライト。
- **テーマ史（テーマ別）タブ**: 単元をまたぐ流れを縦線でつないで表示。
- **トピックタブ**: 折りたたみ表示（「続きを読む ▼」）。
- **クイズタブ**: 単元・分野・形式をチップで複数選択（空になったら自動で全選択に戻す）、問題数、「苦手な問題を優先」。回答後に正解を緑・誤答を赤に着色して解説を表示。最後に得点・正答率・講評・まちがえた問題の解説一覧。
- **記録タブ**: 解いた問題数／通算正答率／読んだ単元／学習した日数のタイル、単元別・分野別の正答率バー、まちがえた問題トップ10。
- **保存タブ**: ☆した用語と、保存した問題（解答と解説つき）。
- **検索（🔍）**: 用語・人物・できごと・トピック・詳細の小見出しを横断する部分一致検索。
- **URL**: `#u=<単元ID>`（任意で `&s=<サブタブ>`）で単元を直接開ける。初回読み込みと `hashchange` の両方で処理する。

## 7. クイズの実装で注意している点

1. **選択肢のシャッフルは `sel` と `src` のみ。** `ord`（Ⅰ−Ⅱ−Ⅲ）と `cmb`（a・c など）は選択肢の並び自体が設問の一部なので、シャッフルすると設問が壊れる。表示順は `session.cur.idx` に持ち、正解の表示位置は `idx.indexOf(q.a)` で求める。
2. **絞り込みチップが空にならないようにする。** トグルの結果 `Set` が空になったら、その場で全選択に戻す。
3. **二重回答の防止。** `b.disabled = true` に加えて `session.cur.answered` フラグでも弾く。
4. **問題の `id` は学習記録の主キー。** あとから変えない。削除に備えて参照側は `.filter(Boolean)` する。
5. **シャッフルしない形式は正解位置が偏る。** `cmb` / `ord` は形式ごとに正解インデックスを集計し、最大でも5割を超えないようにする（偏りの直し方は `知見.md` 2.8 / 8.3）。

## 8. 見た目

- 分野ごとに基調色・背景色・フォントを変える（日本史・世界史・倫理・国語3分野は明朝体、地理・政治・経済・理科・数学・英語はゴシック体）。生成時に `style.css` へ差しこむ。
- 色はすべて CSS 変数。ダークは `@media (prefers-color-scheme: dark)` と `:root[data-theme="dark"]` の**両方**に定義する（設定で強制切替できるため）。
- ダークでは `--primary` が明るくなるので、その上の文字 `--primary-text` を暗い色にする。ヘッダーだけは別変数 `--header-bg` / `--header-fg` を使い、明暗どちらでも濃い色＋白を保つ。
- 単元ごとの色は `--ec` に入れ、カードの左線・年表の点・ヒーローの背景で使い回す。`color-mix()` 非対応ブラウザ向けに `background: var(--ec);` を先に書いて上書きさせる。
- 480px 以下ではタブをアイコンのみ（選択中だけラベル）にし、カードを1列にする。

## 9. 検索（3階層）

| 階層 | 対象 | 実装 |
|---|---|---|
| ポータル | 全18分野270単元 | `search.js` ＋ `search-index.js`（`data-subject` が空） |
| 教科ページ | その教科の分野だけ | 同じ `search.js`（`data-subject="社会"`、`data-base="../"`） |
| 各アプリ | 年表・統計・用語の本文 | `app.js` の 🔍（データを直接検索） |

- `search-index.js` は `SEARCH_FIELDS`（分野18件）と `SEARCH_UNITS`（単元270件）の2つの配列。
- 索引に入れるのは**単元の見出し（名前・よみ・サブタイトル・キャッチ・絵文字）と、用語・人物の名前だけ**。説明文は入れない。用語3758件を含めて約150KB。本文の検索は各アプリの🔍に任せる。
- URL は生成時に `encodeURIComponent` 済み（日本語フォルダ名のため）。
- ポータルと教科ページで同じ `search.js` を使い、違いは `document.body.dataset`（`subject` / `base`）だけで表す。
- 結果から単元を開くと `#u=<単元ID>` 付きで遷移し、その単元が直接開く。

| `index.base.html` | 画面の骨組みの原本。タブ名・絵文字・プレースホルダーも `apps.json` から差し替える |
| `style.base.css` | 配色とフォントを差しこむ原本 |
| `apps.json` | 分野ごとの設定（`dir` `subject` `slug` `port` `title` `icon` `desc` 配色20色 `unit` `list` `wordsTab` `listIcon` `themeWord` `kinds` ほか）。雛形元の社会4分野（日本史・世界史・地理・政治・経済）は含まず、生成で作った14分野ぶんが入っている |
| `gen.py` | 各分野へ `index.html` / `style.css` / `app.js` / `sw.js` / `manifest` / 起動スクリプトを生成。出力先は `<教科>/<分野>`。ルートは**スクリプトの位置から**求める（`GEN_BASE` で上書き可）。書いたファイルを1つずつ出力する |
| `mkicons.py` | アイコン4種（192 / 512 / maskable / apple-touch）を生成 |
| `mkindex.js` | 全分野の単元データから `search-index.js` を生成（`node tools/tpl/mkindex.js`） |
| `check.sh` | 1分野分のデータ検証 |

**データを書いたら必ず検証する。** 確かめるのは次の7点。

1. 総数と単元別の内訳（各単元12問以上）
2. `id` の重複がないこと（単元・問題とも）
3. すべての問題で `0 <= a < choices.length`
4. `ord` は6択、それ以外は4択
5. `type:'src'` の問題に `src` 本文があること
6. `era` が `UNITS` に実在すること
7. 本文（`q` / `src` / `exp` / `choices`）に日本語以外の語が混入していないこと

7はファイル全体を `grep` すると `id:'q-kikou-4'` のようなコード部分が大量に引っかかるので、Node で読んで**本文フィールドだけ**を調べる。
**基準は教科によって変える。**

| 教科 | 検出する語 | 理由 |
|---|---|---|
| 社会・国語 | 2文字以上のラテン文字（`GDP` `SNS` などは許可リスト） | `village` `market` のような混入を拾う |
| 理科・数学 | 4文字以上で、かつ「全部小文字」か「先頭だけ大文字」の語 | `mg` `ZnSO` `IBLsinθ` のような化学式・数式を除く |
| 英語 | ラテン文字は検出しない。キリル文字・ハングル・アラビア文字のみ | 例文が英語なので、ラテン文字を疑うと全部ひっかかる |

あわせて `cmb` の正解が `/^[ab]・[cd]$/` に一致するか、解説に書いた番号と `a` が一致するか、形式ごとの正解位置が偏っていないかも機械的に確かめる（経緯は `知見.md` 2.6〜2.8）。

> 現在の `check.sh` は冒頭にパスを直書きしており、教科の分岐も理科ぶんしか入っていない（`知見.md` 11.1 / 11.2）。作り直すときは、パスをスクリプトの位置から求め、教科 → 基準の対応を表としてスクリプト内に持たせる。

## 11. オフライン対応と更新手順

各アプリと、ポータル（`学習アプリ/sw.js`）がそれぞれ Service Worker をもつ。いずれもネット優先・失敗したらキャッシュ。
Service Worker のスコープは置かれたディレクトリなので、アプリのフォルダは各アプリの SW が、それ以外はポータルの SW が担当する。ポータル側のキャッシュ一覧にアプリのファイルは含めない。

**更新手順**: ファイルを変えたら、そのアプリの `sw.js` の `CACHE` と `index.html` の `?v=` を**同じ番号で**上げる。ローカル確認のときも上げる。
索引（`search-index.js`）を作り直したときは、**ポータルと教科ページ5枚の `?v=` を同じ番号に揃え**、ポータルの `sw.js` の `CACHE` も上げる（現在は 8）。

## 12. 内容を増やすとき

- **単元を足す**: `UNITS` に追加するだけ。カード一覧・年表・検索インデックス・クイズの絞り込みチップはすべて `UNITS` から自動生成される。終わったら `mkindex.js`。
- **問題を足す**: `QUIZ` に追加。`id` は重複させない。`ord` は6択、`cmb` は `['a・c','a・d','b・c','b・d']` で統一する。
- **分野を足す**: `apps.json` に1件足して `gen.py`。`data-units.js`（`APP` ＋ `UNITS`）・`data-quiz.js`・`data-themes.js` を書く。`app.js` の変更は不要。教科ページのカードと `mkindex.js` の再実行、`?v=` の更新を忘れない。
- **教科を足す**: 教科フォルダと教科ページ（`data-subject` / `data-base` を持つ分野選択ページ）を作り、ポータルにカードを足す。`mkindex.js` の `SUBJECTS` に教科名を加える。
