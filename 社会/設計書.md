# 社会（日本史・世界史・地理・政治経済）設計書

最終更新: 2026-10-19

## 1. 概要

高校の社会科5分野を、単元ごとの解説と大学入学共通テスト形式のクイズで学べるアプリ群。
HTML / CSS / JavaScript だけで動き、ビルド不要・外部 API なし。PWA としてホーム画面に追加でき、完全にオフラインで使える。

- ポータル: `学習アプリ/index.html`（教科）→ `社会/index.html`（分野）→ 各アプリ
- ローカル起動: `学習アプリ/start.command`（Mac）／`start.bat`（Windows） → http://localhost:8771/
- 各アプリは単独でも起動できる（日本史8766 / 世界史8767 / 地理8768 / 政治・経済8769 / 倫理8776）

### 収録量

| 分野 | 単元 | 年表・統計 | 用語 | 人物・事例 | 詳細項目 | トピック | テーマ史 | クイズ |
|---|---|---|---|---|---|---|---|---|

## 2. ファイル構成

```
学習アプリ/
├── index.html  style.css  sw.js  manifest.webmanifest  icon-*.png
├── start.command  start.bat  .claude/launch.json
└── 社会/
    ├── index.html                     ← 分野選択
    ├── 設計書.md  知見.md  再現プロンプト.md
    └── <分野>/
        ├── index.html                 ← 画面の骨組み。CSS/JSを ?v=N 付きで読む
        ├── style.css                  ← 分野ごとの配色・フォント
        ├── app.js                     ← 動作（5分野で共通。ラベルは APP から読む）
        ├── data-units.js              ← APP 設定 ＋ UNITS（単元データ）
        ├── data-quiz.js               ← QUIZ（クイズ）
        ├── data-themes.js             ← THEMES（テーマ史）
        ├── sw.js  manifest.webmanifest  icon-*.png
        └── start.command  start.bat  .claude/launch.json
```

読み込み順は `data-units.js` → `data-quiz.js` → `data-themes.js` → `app.js`。
各データファイルの末尾に `module.exports` があり、Node から `require()` して検証できる（ブラウザでは `typeof module !== 'undefined'` で無視される）。

**日本史だけ歴史的な事情で `data-eras.js` / 変数名 `ERAS` を使っている。** 最初に単独のアプリとして作り、あとから3分野を汎用化したため。動作は同じで、他の3分野は `data-units.js` / `UNITS` に統一されている。

## 3. 1つのエンジンを5分野で共有するしくみ

画面の動作（`app.js`）は5分野で共通で、分野ごとの違いはすべて `data-units.js` 冒頭の `APP` オブジェクトに切り出してある。

```js
const APP = {
  key: 'chiri.v1',             // localStorage のキー
  title: '地理マスター',
  icon: '🗺️',
  unitWord: '分野',             // 「時代」「分野」「単元」
  listWord: '統計',             // 「年表」「統計」
  leadUnits: '…',               // 一覧画面の説明文
  searchPlaceholder: '…',
  cats: ['自然', '産業', '人口・都市', '地誌'],       // クイズの分野区分
  typeLabels: { sel:'正誤判定', cmb:'組合せ', ord:'順位配列', src:'資料読取' },
  typeNotes: ['…'],             // 出題形式の説明（クイズ設定画面）
};
```

`app.js` の `applyBranding()` が起動時にこれを画面へ反映する（タイトル、タブ名、サブタブ名、見出し、プレースホルダー）。
**分野を1つ増やすときに `app.js` を触る必要はない。**

## 4. データ構造

### 4.1 `UNITS`（単元データ）

```js
{
  id: 'kikou',                   // 一意のID。クイズの era と対応
  name: '気候', yomi: 'きこう',
  span: '大気大循環・ケッペンの気候区分',  // 表示用のサブタイトル
  n0: 300, n1: 399,              // 並べ替え用の範囲（歴史は西暦、地理は分野番号）
  icon: '☀️', color: '#039be5',  // 単元色。CSS 変数 --ec に流しこむ
  catch: '一行キャッチコピー',
  summary: ['段落1', '段落2', …],
  sections: [{ t:'見出し', items:[{ h:'小見出し', b:'本文' }, …] }, …],
  keywords: [{ w:'用語', y:'よみ', d:'説明' }, …],
  people:   [{ n:'人名・事例', y:'よみ', d:'説明' }, …],
  events:   [{ n:301, y:'表示用', t:'項目', d:'補足' }, …],   // n が並べ替えキー
  topics:   [{ t:'題', lead:'リード', body:['段落', …] }, …]
}
```

- 歴史2分野の `events` は**年表**（`n` は西暦、紀元前はマイナス）。
- 地理の `events` は**統計データ**（`n` は「分野番号×100＋通し番号」。全体一覧で分野ごとにまとまるようにしている）。
- 地理の `people` は人物ではなく**まぎらわしい用語の対比**に使っている（タブ名も「用語・事例」）。

### 4.2 `QUIZ`

```js
{
  id: 'q-kikou-4',   // 一意。学習記録のキーなので変更しない
  era: 'kikou',      // UNITS の id
  type: 'src',       // sel / cmb / ord / src
  cat: '自然',        // APP.cats のいずれか
  lv: 2,             // 1=基本 2=標準 3=やや難（★の数）
  q: '設問文（\n で改行可）',
  src: '史料・資料本文',   // type:'src' のときのみ
  choices: ['①の文', …],  // ord は6択、それ以外は4択
  a: 0,              // 正解のインデックス（choices の元の並び順）
  exp: '解説'
}
```

**出題形式は共通テストの定番に合わせている。**

| type | 日本史・世界史 | 地理 | 政治・経済 |
|---|---|---|---|
| `sel` | 正誤判定 | 正誤判定 | 正誤判定 |
| `cmb` | 組合せ（a〜dの正誤） | 組合せ | 組合せ |
| `ord` | 年代配列（Ⅰ〜Ⅲを古い順） | 順位配列（数値の大きい順） | 年代配列 |
| `src` | 史料 | 資料読取（統計表） | 資料・条文 |

### 4.3 `THEMES`

`{ id, icon, title, color, lead, steps: [{ era:'表示用のラベル', t, b }, …] }`。
`steps[].era` は `UNITS.id` ではなく「飛鳥・奈良」「気候」のような表示用の文字列（複数単元にまたがるため）。

## 5. 保存データ（localStorage）

キーは `APP.key` の1つだけ（`nihonshi.v1` / `sekaishi.v1` / `chiri.v1` / `seikei.v1`）。
`load()` で既定値とマージするので、項目を追加しても既存ユーザーが壊れない。読み書きは try/catch で囲む。

```js
{
  read:   { unitId: true },              // 開いた単元（一覧に「読了」バッジ）
  qstat:  { qid: { o: 出題数, x: 誤答数 } },
  erastat:{ unitId: { o, c } },
  catstat:{ '自然': { o, c } },
  days:   { '2026-10-19': その日に解いた数 },
  sessions: [{ d, n, c }],               // 直近300回
  savedWords: [{ w, y, d, era }],
  savedQuiz:  [qid, …],
  set: { furigana, shuffle, fontsize, theme }
}
```

分野ごとにキーが違うので、学習記録は混ざらない。

## 6. 画面

- **単元タブ**: カード一覧 → 詳細（6つのサブタブ: 概要／詳細／用語・人物／年表・統計／トピック／クイズ）。`◀ ▶` で前後の単元へ（サブタブは維持）。ヘッダー左の `◀` で分野一覧へもどる。
- **年表・統計タブ**: 全単元を通しで一覧。単元チップで絞り込み、テキスト検索で該当語を `<mark>` でハイライト。
- **テーマ史タブ**: 単元をまたぐ流れを縦線でつないで表示。
- **トピックタブ**: 折りたたみ表示（「続きを読む ▼」）。
- **クイズタブ**: 単元・分野・形式をチップで複数選択（空になったら自動で全選択に戻す）、問題数、「苦手な問題を優先」。回答後に正解を緑・誤答を赤に着色して解説を表示。最後に得点・正答率・講評・まちがえた問題の解説一覧。
- **記録タブ**: 解いた問題数／通算正答率／読んだ単元／学習した日数のタイル、単元別・分野別の正答率バー、まちがえた問題トップ10。
- **保存タブ**: ☆した用語と、保存した問題（解答と解説つき）。
- **検索（🔍）**: 用語・人物・できごと・トピック・詳細の小見出しを横断する部分一致検索。

## 7. クイズの実装で注意している点

1. **選択肢のシャッフルは `sel` と `src` のみ。** `ord`（Ⅰ−Ⅱ−Ⅲ）と `cmb`（a・c など）は選択肢の並び自体が設問の一部なので、シャッフルすると設問が壊れる。表示順は `session.cur.idx` に持ち、正解の表示位置は `idx.indexOf(q.a)` で求める。
2. **絞り込みチップが空にならないようにする。** トグルの結果 `Set` が空になったら、その場で全選択に戻す。
3. **二重回答の防止。** `b.disabled = true` に加えて `session.cur.answered` フラグでも弾く。
4. **問題の `id` は学習記録の主キー。** あとから変えない。削除に備えて参照側は `.filter(Boolean)` する。

## 8. 見た目

- 分野ごとに基調色・背景色・フォントを変える（歴史2分野は明朝体、地理と政経はゴシック体）。生成時に `style.css` へ差しこむ。
- 色はすべて CSS 変数。ダークは `@media (prefers-color-scheme: dark)` と `:root[data-theme="dark"]` の**両方**に定義する（設定で強制切替できるため）。
- ダークでは `--primary` が明るくなるので、その上の文字 `--primary-text` を暗い色にする。ヘッダーだけは別変数 `--header-bg` / `--header-fg` を使い、明暗どちらでも濃い色＋白を保つ。
- 単元ごとの色は `--ec` に入れ、カードの左線・年表の点・ヒーローの背景で使い回す。`color-mix()` 非対応ブラウザ向けに `background: var(--ec);` を先に書いて上書きさせる。

## 9. オフライン対応

各アプリと、ポータル（`学習アプリ/sw.js`）がそれぞれ Service Worker をもつ。いずれもネット優先・失敗したらキャッシュ。
Service Worker のスコープは置かれたディレクトリなので、アプリのフォルダは各アプリの SW が、それ以外はポータルの SW が担当する。

**更新手順**: ファイルを変えたら、そのアプリの `sw.js` の `CACHE` と `index.html` の `?v=` を**同じ番号で**上げる。ローカル確認のときも上げる。

## 10. 内容を増やすとき

- **単元を足す**: `UNITS` に追加するだけ。カード一覧・年表・検索インデックス・クイズの絞り込みチップはすべて `UNITS` から自動生成される。
- **問題を足す**: `QUIZ` に追加。`id` は重複させない。`ord` は6択、`cmb` は `['a・c','a・d','b・c','b・d']` で統一する。
- **分野を足す**: 雛形（`index.html` / `style.css` / `app.js`）をコピーし、`data-units.js` の `APP` を書き換えるだけ。`app.js` の変更は不要。

### 検証

データを書いたら、次の点を Node で機械的に確かめる。

1. 総数と単元別の内訳（各単元12問以上）
2. `id` の重複がないこと
3. すべての問題で `0 <= a < choices.length`
4. `ord` は6択、それ以外は4択
5. `type:'src'` の問題に `src` 本文があること
6. `era` が `UNITS` に実在すること
7. 本文（`q` / `src` / `exp` / `choices`）に日本語以外の語が混入していないこと

7番はファイル全体を `grep` すると `id:'q-kikou-4'` のようなコード部分が大量に引っかかるので、Node で読んで**本文フィールドだけ**を調べる（詳しくは `知見.md`）。
